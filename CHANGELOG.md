# Changelog

Формат: версия фронтенда (`conf/extver`) — ключевые изменения.

## 50 — UI один-в-один с SafeLine
- Панельный интерфейс SLExt приведён к стилю дашборда SafeLine (карточки/кнопки/инпуты/таблицы/
  табы/KPI/бейджи/аккордеоны/тосты/тултипы), тёмная тема — точная копия SafeLine Pro.
- Публичные страницы (зал ожидания, challenge, auth, dynamic, gate, страницы ошибок) возвращены
  к стоковому виду SafeLine: синий фон #0067B8, белые контролы, щит и футер SafeLine.
- Цвета страниц ошибок: error #FF6666 (403/429/502/504), common #0067B8 (404/465/466);
  поле «Цвет» в SLExt: Страницы — мастер-оверрайд (пусто = по коду).

## 49 — Зал ожидания: найдена причина «никого не пускает»
- Причина: лимиты SafeLine (`max_concurrent=5`, активный таймаут ~3 минуты), когда-то
  занесённые в БД нашим же «подставить в зал» из теста ёмкости. Порог 5 активных
  посетителей при обычном трафике держал очередь постоянно; панельный API CE лимиты
  менять не умеет — их владелец mgt, и на каждом переключении он возвращает свои.
- Свои лимиты: поля в блоке «Зал ожидания» (порог включения / таймаут сессии, мин /
  макс. очередь). Применяются перед каждым включением зала, воркер выравнивает строку
  конфига, если SafeLine вернул свои значения; параллельно пишем waiting.yaml.
- Кнопка **«Сбросить очередь»** — перезапуск модуля очереди на случай залипшего
  состояния (сайт мигает 2–5 секунд).
- Страница очереди: возвращён WebSocket-выпуск (как в нативной `waiting.js`) с откатом
  на опрос, состояние «очередь переполнена» теперь перезагружается автоматически.
- «Подставить в зал» из теста ёмкости больше не ставит порог ниже 100.
- Скорость: расчёт трафика для авто-режима читал весь часовой лог (25 МБ) и API отвечал
  13–22 секунды — отсюда «вечная загрузка». Теперь скан хвоста лога + кэш 60 с (ответ ~0.1 с).

## 45 — Переписан зал ожидания (надёжные включение/выключение)
- Единая точка переключения (`wr_apply`): mgt → подтверждение факта → состояние; ошибки SafeLine
  показываются в UI, ничего не «зависает» в ожидании.
- После перегенерации конфига SafeLine (mgt перезаписывает сайт при переключении зала) патчи
  восстанавливаются **быстро и в фоне** (`site_patch_fast` + дебаунс), а воркер каждые 20 с
  проверяет маркеры и чинит их сам. Тяжёлый `apply-injection` больше не гоняется на каждый клик.
- Рабочий токен панели выбирается живой проверкой (mgt отклонял часть токенов, например с
  несогласованным 2FA) — из-за этого «плавали» чтения состояния и авто-режим.
- Воркер: сверка факта и состояния, ретраи с backoff, понятные ошибки.
- Авто-режим вынесен в чистую функцию (`bin/wr_policy.py`) и покрыт юнит-тестами
  (`tests/wr_policy_test.py`, гоняются в CI): гистерезис, пороги, cooldown, min_off.
- UI: живое обновление раз в 5 с без «вечной загрузки», кнопка блокируется на время операции,
  тексты ошибок и статус операции видны, «состояние неизвестно» — если SafeLine недоступен.
- Страница очереди: только опрос (без WebSocket), backoff при ошибках, пауза в скрытой вкладке.

## 43 — Редактирование пользователя из нативного списка
- Кнопка «⋯» в строке пользователя (Settings → Management → User) открывает редактор SLExt:
  роль (администратор/оператор/наблюдатель/настраиваемый), права, домены, смена пароля, удаление.
  Нативное меню действий (Pro-гейт) полностью подавлено.
- Проверено e2e: смена роли и пароля из редактора, вход с новым паролем.
- Хотфикс зала ожидания: бэкапы конфигов сайтов уносятся из `sites-enabled` (файл
  `IF_*.slext-orig` попадал в `include IF_*` и ломал `nginx -t`, из-за чего mgt не мог
  переключить зал — «не выключается» и вечная загрузка); вотчдог теперь проверяет `nginx -t`
  и сам переприменяет патчи при поломке конфига.

## 42 — Кнопка ADD USER работает через SLExt
- Нативная кнопка **ADD USER** (Settings → Management → User) перехватывается и открывает
  форму создания SLExt вместо окна «license required»; после создания страница обновляется,
  и пользователь виден в нативном списке.
- Подтверждено end-to-end: созданный пользователь входит в панель обычным способом
  (формат хеша SafeLine CE: PBKDF2-HMAC-SHA256/1024/32, соль ascii).

## 41 — Устойчивость API + управление учётками
- Починен обрыв связи панели с API: self-healing прокси `/extapi` (http://gateway:8787),
  API слушает docker-мост, ufw-правило для сети контейнеров, systemd-вотчдог раз в минуту.
- Производительность: кэш аналитики атак (60 с), таймауты обработчиков, увеличенная очередь.
- В блоке «SLExt: Доступ» (Settings) добавлены создание учётной записи, смена пароля и удаление
  (нативно это Pro-функция «нужна активация лицензии»). Хеш совместим с SafeLine
  (PBKDF2-HMAC-SHA256/1024/32).

## 40 — Доступ в оригинальном интерфейсе
- Матрица прав перенесена из вкладки SLExt в нативный раздел панели
  (**Settings → Management → блок «SLExt: Доступ»**); вкладка «Доступ» убрана — без дублей.
- Деплой (CI/CD) больше не удаляет локальные `tools/` — обновляются только управляемые каталоги.

## 39 — Матрица доступа
- Роли (Администратор / Оператор / Наблюдатель / Настраиваемый), 22 права по разделам.
- Ограничение доступа по доменам: фильтрация статистики и запрет действий по чужим доменам (403).
- Вкладка **Доступ** в панели, чип текущего пользователя, скрытие вкладок и блокировка кнопок.
- Серверные проверки прав на всех эндпоинтах, защита «последнего администратора».

## 38 — Прокси-аналитика и DNS/TLS
- Компактный раздел «Проксирование» в стиле Cloudflare: один график с переключателем метрик
  (запросы/трафик/задержки/ошибки), уникальные IP, referer-источники, сворачиваемые детали.
- Новый раздел **DNS и TLS**: A/AAAA+TTL, задержка резолвера, SPF/DMARC, TLS-сертификаты
  (издатель, дни до истечения), автопроверка каждые 5 минут, история 2 суток.
- Собственный DNS-клиент (stdlib), ротация `slext_traffic.log`, кэш метрик.

## 37 — Тест ёмкости без отключения защиты
- Режим по умолчанию — «напрямую в бэкенд» (защита не затрагивается).
- Авто-пауза защиты для режима «через WAF» (частотные правила SafeLine + CrowdSec-бансер)
  с автоматическим возвратом.
- Архив отчётов (10 последних): открыть/скачать HTML/удалить; расширенный анализ теста
  (устойчивый RPS, деградация, итоги, запросы и длительность стадий).
- Прогрев цели и авто-очистка своих банов CrowdSec перед тестом.

## 35–36 — Типографика и пояснения
- Шрифты один-в-один с панелью (Inter, размеры/веса как у родных элементов).
- Тултипы при наведении ко всем метрикам и настройкам; исправлен шрифт вкладок.

## 30–34 — Интеграция в интерфейс
- SLExt — полноценная вкладка в левом меню (вместо оверлея/плавающей кнопки).
- Контент под шапкой панели, нативные табы, авто-закрытие при переходе по меню,
  единая подсветка активного пункта. Скрытие разделов при нехватке прав (до появления матрицы).

## 28–29 — Порядок в настройках
- Все настройки переехали в единую вкладку; удалён мёртвый код, исключения апселл-скрытия
  для всех карточек, скрытие панели на логине.

## 25–27 — Статистика и авто-алгоритм
- Детерминированный авто-режим зала ожидания (пороги в запросах/мин, «удержание»,
  паузы, приоритет ручного управления, журнал решений).
- Исправлена статистика зала (встали/обслужено/средний wait/отказы) и учёт атак
  (только реальные, без служебных записей).

## 21–24 — Фиксы дашборда
- Устранено исчезновение 3D-глобуса на дашборде (карточки вынесены из MUI-грида).
- Идемпотентный порядок карточек, защита от скрытия контейнера, стабильная загрузка.

## 7–20 — Базовая функциональность
- Skip decryption с гейтом первого захода (без `document.write`), свои страницы ошибок,
  гео-блокировка, зал ожидания с кастомной страницей, уведомления/алерты/syslog/бэкапы,
  балансировщик, экспорт, тема, скрытие апселлов, фиксы сжатия и 404 для API.
