# Changelog

Формат: версия фронтенда (`conf/extver`) — ключевые изменения.

## 55 — гибридная интеграция SLExt в родную панель + ре-скин
- SLExt больше не «окно поверх панели»: разделы открываются **в родной контентной зоне**,
  родная шапка и drawer остаются на месте; кнопка «Закрыть» возвращает родную страницу.
- Навигация — **под-меню с группами прямо в родном drawer**: пункт SLExt раскрывает
  Мониторинг / Доступность / Защита / Система; подсветка активного раздела, значок зала
  ожидания, права скрывают недоступные пункты (самовосстановление при ре-рендере React).
- Ре-скин обеих тем: тёмная — консоль в стиле SafeLine (по умолчанию), светлая приведена
  к общему виду (скругления, primary-кнопки и активные пункты меню в фирменном цвете,
  таблицы/табы/чекбоксы). Родные страницы SafeLine остаются рабочими.
- Совместимость с обновлениями SafeLine сохранена: всё идемпотентно, вотчдог и
  `apply-injection` возвращают пункты меню и версии `?v=` после перегенерации конфигов.
- Данные и API не менялись — все разделы, действия и права работают как раньше.

## 54 — редизайн интерфейса + аудит: ошибки, гонки, очередь, уведомления
- **Исправлена ошибка nginx `cannot load certificate key /opt/slext/conf/mgt.key`:**
  install.sh и apply-injection.sh теперь создают/восстанавливают парную TLS-пару
  `mgt.crt`+`mgt.key` (проверка совпадения по modulus, права 600/644) и перечитывают
  nginx хоста при её пересоздании.
- **Новый UX/UI (тёмная консоль в стиле SafeLine):** боковая навигация с группами
  (Мониторинг / Доступность / Защита / Система), топбар с хлебными крошками, статусами,
  профилем и кнопками «Обновить/Тема/Закрыть», адаптивный off-canvas сайдбар на мобильных.
  Добавлен **Дашборд**: плитки-сводка по всем разделам с переходами в разделы.
  CrowdSec переехал из «Обзора» в «Безопасность». Функционал и API не менялись.
- **Очередь зала ожидания:** исправлена выдача cookie (`Set-Cookie` не отправлялся —
  каждый опрос плодил ghost-посетителей и забивал очередь), добавлена блокировка
  `QUEUE_STATE` (гонки/`RuntimeError`), продление отметки ожидающего (не терял место
  через 15 минут), ранний выход при выключенном зале; закрыта CRLF/unicode-инъекция в
  редиректе `handle_queue_go`; `queue_sync_map` проверяет `nginx -t`; stats учитывает
  per-site TTL.
- **Авто-режим зала:** `real_rate_pm` читает логи от свежих к старым (ротации больше не
  давали rate=0), расписание поддерживает окно через полночь (`22:00–06:00`) и часы вида
  `9:00`.
- **Уведомления:** у Telegram и Discord свои курсоры — сбой одного канала больше не
  зацикливает очередь и не спамит дублями второй.
- **Надёжность API:** `load_state` не падает и не теряет конфиг на битом state.json
  (типы нормализуются, некорректные значения — clamp), `parse_ts` не зависит от локали,
  gzip-логи с `EOFError` не роняют `/api/traffic` и `/api/security`, `last_hour` реально
  считается, `prev_total` учитывает фильтры, `/api/attacks.sites` ограничен доменами
  пользователя, LB: блокировки `NODES`, валидация адресов, атомарная запись конфига с
  откатом при `nginx -t`, бэкап без гонки `/tmp` и с обработкой ошибок tar,
  тест ёмкости не может идти дважды и чистит `LT_JOBS`.
- **Права:** добавлены `lb.view` (просмотр) и `lb.edit` (изменение) — балансировка больше
  не доступна любому авторизованному; `/api/security` и `/api/traffic` под `proxy.view`.
  Итого 24 права (матрица и документация обновлены).
- **Установка/удаление:** починен quoting gzip-патча панели (команда всегда падала),
  `patch_index.py` идемпотентен и восстанавливает теги при потере маркера, uninstall
  останавливает watchdog/teststub, восстанавливает конфиги из `/opt/slext/backups/nginx`
  до удаления каталога, не кладёт `.slext-removed` в include-каталог; добавлен
  `.gitattributes` (LF для скриптов).

## 53.1 — надёжный деплой (фронт без изменений)
- **Причина красного пайплайна 30.09:** деплой проверял здоровье API через 2 секунды
  после рестарта, а API стартовал синхронно с `skip_apply` (nginx -t + reload) и не
  успевал открыть сокет → `connection refused`, exit 7. Теперь API поднимает HTTP-порты
  сразу (skip_apply — в фоне), старт ~0.6 с.
- Скрипт деплоя ждёт готовности API до 60 с с ретраями; при неудаче показывает
  `journalctl -u slext-api` и **автоматически откатывается** на предыдущую версию
  из `/opt/slext.old`, после чего завершается с ошибкой.
- Самообновление `/usr/local/bin/slext-deploy` из staging (иначе CI запускал бы
  старую копию скрипта) + защита от CRLF и таймауты на ssh/apt/docker, чтобы шаг
  не мог зависнуть.
- Пайплайн: `set -euo pipefail`, `ConnectTimeout`/`ServerAliveInterval` и `timeout 900`
  вокруг удалённой команды деплоя.

## 52.1 — полный аудит: исправления (фронт без изменений)
- **Права (критично):** `/api/access/user*` (создание/удаление/смена пароля) больше не
  доступны любому авторизованному — только администратору; удалён legacy `/api/telegram*`.
- **Петля релоадов nginx (критично):** патчер был неидемпотентен — regex `include
  custom_params` без якоря добавлял 8 пробелов в начало строки при каждом прогоне
  (`slext-apply.timer` каждые 2 мин → nginx reload каждые 2 мин и рост файла). Заякорен,
  конфиги нормализованы; `site_markers_ok` больше не требует маркеров от служебных сайтов.
- **Гонка патчера (критично):** параллельные вызовы патчера рвали конфиги (emerg
  `unexpected end of file`) — атомарная запись (tmp+rename) и общий `PATCH_LOCK`.
- **Уведомления:** события ниже порога больше не застревают в очереди навсегда; пороги
  telegram/discord применяются независимо.
- **Тест ёмкости:** origin-режим берёт backend испытываемого сайта (был жёстко `backend_1`);
  авто-пауза защиты выключает правила только тестируемого сайта (и глобальные).
- **Мультисайт:** `t1k_add_user_data`/`tx_add_user_data` в `@slext-plain` — по номеру сайта
  (был жёстко `"1"`); `/api/waiting/extras` отдаёт состояние mgt своего сайта.
- **Очередь:** анти-накрутка — один IP получает новый слот не чаще раза в минуту
  (свой токен всегда проходит); удалён опасный `/api/waiting/reset` (рестарт tengine).
- **Надёжность:** глобальный перехват ошибок в GET/POST (JSON 500 вместо обрыва соединения);
  битый `state.json` сохраняется как `.bad`; бэкап-архивы `600`; при сбое БД список сайтов
  не «сбрасывается».
- **Установка:** в репозиторий добавлен `systemd/slext-apply.service` (без него свежая
  установка ломалась); `install.sh` перезапускает API; деплой сохраняет `geo/` и
  `lb-upstreams.conf`; удалены неиспользуемые скрипты-миграции.

## 52 — Зал ожидания: мгновенный допуск без «мигания» + русская страница
- Новый механизм допуска (rewrite-гейт вместо auth_request): если место есть — посетитель
  сразу попадает на сайт (два быстрых 302 через API), страница очереди не мелькает.
  Если мест нет — показывается страница очереди. Ассеты (`Accept: */*`) не затрагиваются.
- Причина прежнего «мигания»: гейт стоял не в том локале — запросы с `nrgpass` уходят
  в `@slext-plain` (skip-дешифровка), гейт добавлен и туда, и в основной локал.
- Страница очереди: русские дефолты (title/message/note/brand), миграция англоязычных
  текстов SafeLine на русские; редизайн (кольцо прогресса, место «N из M»), после допуска
  страница переходит на исходный адрес (`to`), а не перезагружает себя.
- API: `/api/queue/go` (допуск/редирект), `/api/queue/admit` (резерв), `/api/queue/status`;
  per-site настройки в `state.json`; map-файл гейта управляется API (добавление/снятие
  сайтов без правки конфигов), `queue_patch_reload` больше не нужен для тумблера.
- Патчер сайтов: гейт-строки постоянные (в двух локалах), автоматическая чистка старых
  схем (map-if, auth_request), нормализация маркеров; apply-injection создаёт map-файл.
- E2E на тестовом контуре: допуск при наличии места, постановка в очередь при лимите,
  сброс очереди, выключение; проверено на `test.slext.local`.

## 51 — Свой зал ожидания (SLExt) + тестовый контур
- **Свой зал очереди** вместо капризного нативного: cookie-гейт в nginx + наш API.
  Считает **посетителей** (по cookie), лимиты полностью наши: порог одновременных,
  удержание слота, макс. очередь — настраиваются в блоке «Зал ожидания» и применяются мгновенно.
  Страница очереди — наша (позиция, живой опрос, авто-вход), «Сбросить очередь» мгновенный.
- **Тестовый контур**: сервис-заглушка `slext-teststub` и сайт `test.slext.local` в SafeLine —
  все сценарии (зал, страницы, гейт) проверяются без риска для боевого сайта.
- **Мультисайтовые фиксы**: патчи сайтов больше не зашиты под `backend_1` (свой backend,
  своя схема, свой custom_params у каждого сайта); служебные сайты без backend
  (portal/auth) не патчатся и очищаются от следов; map-файл очереди управляется API.
- Авто-режим по нагрузке теперь включает/выключает наш зал; нативный зал SafeLine
  не используется (его лимиты CE менять не даёт).
- Скорость: расчёт трафика авто-режима — чтение хвоста лога + кэш (было 13–22 с, стало ~0.1 с).

## 49 — Зал ожидания: найдена причина «никого не пускает»
- Причина: лимиты SafeLine (`max_concurrent=5`, активный таймаут ~3 минуты), когда-то
  занесённые в БД нашим же «подставить в зал» из теста ёмкости. Порог 5 активных
  посетителей при обычном трафике держал очередь постоянно; панельный API CE лимиты
  менять не умеет — их владелец mgt, и на каждом переключении он возвращает свои.
- Свои лимиты: поля в блоке «Зал ожидания» (порог включения / таймаут сессии, мин /
  макс. очередь). Применяются перед каждым включением зала, воркер выравнивает строку
  конфига, если SafeLine вернул свои значения; параллельно пишем waiting.yaml.
- Кнопка **«Сбросить очередь»** — перезапуск модуля очереди на случай залипшего
  состояния (сайт мигает 2–5 секунд).
- Страница очереди: возвращён WebSocket-выпуск (как в нативной `waiting.js`) с откатом
  на опрос, состояние «очередь переполнена» теперь перезагружается автоматически.
- «Подставить в зал» из теста ёмкости больше не ставит порог ниже 100.
- Скорость: расчёт трафика для авто-режима читал весь часовой лог (25 МБ) и API отвечал
  13–22 секунды — отсюда «вечная загрузка». Теперь скан хвоста лога + кэш 60 с (ответ ~0.1 с).

## 45 — Переписан зал ожидания (надёжные включение/выключение)
- Единая точка переключения (`wr_apply`): mgt → подтверждение факта → состояние; ошибки SafeLine
  показываются в UI, ничего не «зависает» в ожидании.
- После перегенерации конфига SafeLine (mgt перезаписывает сайт при переключении зала) патчи
  восстанавливаются **быстро и в фоне** (`site_patch_fast` + дебаунс), а воркер каждые 20 с
  проверяет маркеры и чинит их сам. Тяжёлый `apply-injection` больше не гоняется на каждый клик.
- Рабочий токен панели выбирается живой проверкой (mgt отклонял часть токенов, например с
  несогласованным 2FA) — из-за этого «плавали» чтения состояния и авто-режим.
- Воркер: сверка факта и состояния, ретраи с backoff, понятные ошибки.
- Авто-режим вынесен в чистую функцию (`bin/wr_policy.py`) и покрыт юнит-тестами
  (`tests/wr_policy_test.py`, гоняются в CI): гистерезис, пороги, cooldown, min_off.
- UI: живое обновление раз в 5 с без «вечной загрузки», кнопка блокируется на время операции,
  тексты ошибок и статус операции видны, «состояние неизвестно» — если SafeLine недоступен.
- Страница очереди: только опрос (без WebSocket), backoff при ошибках, пауза в скрытой вкладке.

## 42 — Кнопка ADD USER работает через SLExt
- Нативная кнопка **ADD USER** (Settings → Management → User) перехватывается и открывает

## 41 — Устойчивость API + управление учётками

## 38 — Прокси-аналитика и DNS/TLS

- Новый раздел **DNS и TLS**: A/AAAA+TTL, задержка резолвера, SPF/DMARC, TLS-сертификаты
