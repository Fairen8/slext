# Как участвовать в разработке

## Ветки и правила

| Ветка | Назначение | Правила |
|---|---|---|
| `dev` | интеграция: все фичи и фиксы | PR с 1 одобрением коллеги, проверки CI |
| `prod` | деплой на сервер | **PR только с одобрением владельца (@Fairen8)**, проверки CI |
| `main` | стабильная история | как `prod` |
| `feature/*`, `fix/*`, `docs/*` | рабочие ветки | создаются от `dev`, живут до мержа |

На GitHub для веток включены нативные rulesets (после `bash deploy/apply-github-protection.sh`):
напрямую пушить нельзя — только через PR; `prod`/`main` требуют одобрения владельца.
Дополнительно CI проверяет процесс перед деплоем (`deploy/check-pr-approval.sh`), а
`branch-guard` фиксирует нарушения issue.

## Рабочий цикл

```bash
git checkout dev && git pull
git checkout -b feature/short-name

# ... код ...

bash -n bin/apply-injection.sh          # синтаксис изменённых скриптов
python3 -m py_compile bin/*.py
node --check www/ext.js

git push -u origin feature/short-name
gh pr create --base dev --fill          # PR в dev
```

1. CI (`.github/workflows/ci.yml`) проверит синтаксис и отсутствие секретов.
2. Один коллега ставит approve.
3. Squash-merge в `dev`.

## Выкат на сервер

```bash
git checkout dev && git pull
gh pr create --base prod --head dev --title "release: ..." --body "..."
```

Мерж в `prod` возможен **только после одобрения @Fairen8**; после мержа GitHub Actions
автоматически деплоит на сервер (`sudo /usr/local/bin/slext-deploy`, с бэкапом `/opt/slext.old`).
Ручной запуск деплоя: Actions → **deploy** → Run workflow.

## Стиль кода

- Python — stdlib-first (внешняя зависимость только `psycopg2`), без новых зависимостей без обсуждения;
- фронтенд (`www/ext.js`) — обычный ES5-совместимый JS без сборщиков; стили — `www/ext.css`;
- патчи nginx — только идемпотентно, каждый с маркером `# slext-*`;
- секреты в репозиторий не попадают (CI это проверяет).

## Тестирование

- Статические проверки обязательны (см. выше) — они же в CI.
- Перед PR, меняющим поведение, прогоните на тестовом сервере:
  ```bash
  sudo bash install.sh
  sudo bash tests/verify-install.sh    # ожидается: FAIL=0
  sudo bash tests/auth-test.sh
  ```
- Для UI: проверить вкладку SLExt в панели (разделы не должны содержать ошибок в консоли).

## Коммиты и PR

- Сообщения коммитов: короткие, в повелительном наклонении («добавить», «исправить», «обновить»).
- Один PR — одна задача; в описании — что сделано, как проверять, влияние на деплой.
- Изменения API/прав/деплоя — обязательно с обновлением `docs/`.

## Что не принимается

- Обходы лицензии SafeLine (патчи проверок Pro, подмена лицензии и т.п.);
- секреты и приватные ключи в коде/конфигах;
- изменения, ломающие идемпотентность патчей или теряющие `state.json`/`slext.env`.
