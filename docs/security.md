# Безопасность

## Модель

- **Никаких обходов лицензии.** Платные функции SafeLine (Pro) не включаются и не патчатся;
  их аналоги (skip decryption, страницы ошибок, гео, аналитика) реализованы собственным слоем
  на nginx и в SLExt API. Проверка Pro-тумблеров на стороне SafeLine продолжает работать.
- **Минимальная поверхность.** SLExt API слушает только `127.0.0.1:8787`. Наружу порт не
  открывается; доступ — через панель SafeLine (прокси `/extapi` контейнера `safeline-mgt`).
- **Аутентификация.** Bearer-токен панели проверяется через mgt API
  (`/api/business/account`) с кэшем 60 с; из JWT берётся `Username` для матрицы доступа.
  Все изменяющие и читающие эндпоинты требуют аутентификацию; матрица добавляет права и
  ограничения по доменам (проверки на сервере, `403`).
- **CORS.** Разрешён только origin панели (`https://<mgt>:9443`); публичный
  `/api/waiting/status` ограничен hostname страницы очереди.

## Секреты

| Что | Где | Права |
|---|---|---|
| Пароль PostgreSQL | `/opt/slext/conf/slext.env` | `600` |
| Состояние (токены ботов, webhook'и) | `/opt/slext/conf/state.json` | `600` |
| Токены панели | нигде не хранятся SLExt (только проверяются) | — |

В репозитории секретов нет; `slext.env` не коммитится (`.gitignore` для локальных артефактов,
`conf/slext.env.example` — только шаблон).

## Пауза защиты во время нагрузочного теста

Режим «через WAF» с авто-паузой временно:

- выключает встроенные частотные/защитные правила SafeLine (`mgt_acl_config_v3`, `built_in=true`);
- останавливает `crowdsec-firewall-bouncer`;
- перед стартом снимает баны CrowdSec со своих IP.

Возврат выполняется в `finally` (даже при ошибке теста). Рекомендации:

- запускайте такие тесты в окно низкого трафика и с уведомлением команды;
- после теста проверьте статусы правил и бансера (см. [troubleshooting.md](troubleshooting.md));
- тест «напрямую в бэкенд» (по умолчанию) защиту не трогает — предпочтительный вариант.

## Рекомендации по эксплуатации

1. Заведите отдельного пользователя панели для оперативных действий и выдайте ему роль
   «Оператор» с ограничением по доменам — вместо передачи администратора.
2. Ограничивайте доступ по доменам для подрядчиков/наблюдателей (SLExt → Доступ).
3. Держите включёнными алерты (SLExt → Уведомления) и автобэкапы.
4. Обновляйте SLExt через `git pull && sudo bash install.sh` (идемпотентно, с бэкапом
   исходного конфига при первой установке).
5. Периодически проверяйте `journalctl -u slext-api` и срок TLS-сертификатов (SLExt → DNS и TLS).

## Ограничение ответственности

SLExt — вспомогательный инструмент. Ответственность за конфигурацию SafeLine, правила
фильтрации и доступы остаётся на администраторе. Перед использованием нагрузочного теста
на проде убедитесь, что у вас есть право нагружать целевой сервис.
