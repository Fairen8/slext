# Матрица доступа

Управление — **оригинальный раздел панели SafeLine**: **Settings** → блок **«SLExt: Доступ»**
(виден только администраторам, право `access.manage`). Пользователи берутся
из панели SafeLine (`mgt_user`), идентификация — по JWT-токену панели (поле `Username`),
токен дополнительно проверяется через mgt API (`/api/business/account`).

## Роли

| Роль | Что умеет |
|---|---|
| **Администратор** | все права, включая управление доступом |
| **Оператор** | просмотр всех разделов + зал ожидания (вкл/выкл), бан/разбан CrowdSec, запуск/остановка теста, проверка DNS, балансировка (изменение) |
| **Наблюдатель** | только просмотр (все действия запрещены) |
| **Настраиваемый** | произвольный набор прав из таблицы ниже (без `access.manage`) |

## Ограничение по доменам

Каждому пользователю задаётся список доменов (пусто — все домены). Ограничение действует
на сервере:

- **статистика** (`/api/attacks`, `/api/proxy`, экспорт) фильтруется только разрешёнными доменами;
- **действия** по чужому домену запрещены: зал ожидания (config/extras/page), тест ёмкости
  (start/apply) → `403 нет доступа к домену ...`;
- список сайтов в интерфейсе (зал ожидания, тест ёмкости) ограничивается доменами пользователя.

## Поведение по умолчанию и защита

- Пользователь без явной настройки получает **полный доступ** (роль администратора) —
  ограничения включаются только когда их настроили.
- Сервер запрещает снять права администратора с **последнего администратора**
  (`нельзя снять права администратора с последнего администратора`).
- Все проверки выполняются на сервере (403); интерфейс дополнительно скрывает вкладки и
  блокирует кнопки с подсказкой «Нет доступа».
- В шапке SLExt отображается текущий пользователь, роль и (если заданы) домены.

## Как настроить

1. Панель SafeLine → **Settings** → блок **«SLExt: Доступ»** (доступен администраторам).
2. Для пользователя выбрать роль. Для «Настраиваемый» — отметить нужные права.
3. Указать домены через запятую (подсказка — существующие домены сайтов SafeLine) или
   оставить пустым для доступа ко всем.
4. **Сохранить** — изменения действуют сразу (пользователю достаточно обновить панель).

## Создание пользователей

Нативная кнопка **ADD USER** (Settings → Management → User) в CE требует Pro-лицензию —
при клике открывается окно апгрейда. SLExt перехватывает эту кнопку и открывает свою форму
создания учётной записи (она же есть в блоке **«SLExt: Доступ»**). После создания страница
обновляется, и пользователь появляется в нативном списке.

## Редактирование пользователя

Кнопка **«⋯»** в строке пользователя в нативном списке (нативное меню — Pro-гейт) открывает
**редактор SLExt**: логин (только чтение), роль, права для настраиваемой роли, домены,
новый пароль (пусто — не менять) и удаление. Там же доступны быстрые кнопки в блоке
«SLExt: Доступ» (**Сохранить** / **Пароль** / **Удалить**).

Проверено end-to-end: созданный пользователь **входит в панель обычным способом**, смена роли
и пароля из редактора применяются сразу. Формат хеша совместим с SafeLine CE:
PBKDF2-HMAC-SHA256, соль ascii, 1024 итерации, 32 байта.

**Важно:** SafeLine CE не умеет ограничивать доступ к самой панели (это Pro-RBAC), поэтому
созданный пользователь видит всю панель SafeLine. Выдавайте учётки только доверенным людям,
а ограничения (разделы SLExt и домены) выдавайте в матрице SLExt.
