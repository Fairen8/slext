# Матрица доступа

Управление — вкладка **SLExt → Доступ** (видна только администраторам). Пользователи берутся
из панели SafeLine (`mgt_user`), идентификация — по JWT-токену панели (поле `Username`),
токен дополнительно проверяется через mgt API (`/api/business/account`).

## Роли

| Роль | Что умеет |
|---|---|
| **Администратор** | все права, включая управление доступом |
| **Оператор** | просмотр всех разделов + зал ожидания (вкл/выкл), бан/разбан CrowdSec, запуск/остановка теста, проверка DNS |
| **Наблюдатель** | только просмотр (все действия запрещены) |
| **Настраиваемый** | произвольный набор прав из таблицы ниже (без `access.manage`) |

## Ограничение по доменам

Каждому пользователю задаётся список доменов (пусто — все домены). Ограничение действует
на сервере:

- **статистика** (`/api/attacks`, `/api/proxy`, экспорт) фильтруется только разрешёнными доменами;
- **действия** по чужому домену запрещены: зал ожидания (config/extras/page), тест ёмкости
  (start/apply) → `403 нет доступа к домену ...`;
- список сайтов в интерфейсе (зал ожидания, тест ёмкости) ограничивается доменами пользователя.

## Поведение по умолчанию и защита

- Пользователь без явной настройки получает **полный доступ** (роль администратора) —
  ограничения включаются только когда их настроили.
- Сервер запрещает снять права администратора с **последнего администратора**
  (`нельзя снять права администратора с последнего администратора`).
- Все проверки выполняются на сервере (403); интерфейс дополнительно скрывает вкладки и
  блокирует кнопки с подсказкой «Нет доступа».
- В шапке SLExt отображается текущий пользователь, роль и (если заданы) домены.

## Как настроить

1. SLExt → **Доступ**.
2. Для пользователя выбрать роль. Для «Настраиваемый» — отметить нужные права.
3. Указать домены через запятую (подсказка — существующие домены сайтов SafeLine) или
   оставить пустым для доступа ко всем.
4. **Сохранить** — изменения действуют сразу (пользователю достаточно обновить панель).
