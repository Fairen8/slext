# Возможности

Раздел **SLExt** живёт внутри родного интерфейса SafeLine: пункт в штатном левом меню,
разделы открываются в контентной зоне панели (родная шапка и drawer остаются), навигация —
под-меню с группами (Мониторинг / Доступность / Защита / Система) прямо в родном drawer.
Стиль — тёмная консоль в стиле SafeLine; светлая тема включается переключателем и тоже
приведена к общему виду. Видимость разделов и доступность действий зависят от прав
пользователя (см. [Матрица доступа](access.md)).

## Дашборд

- **Сводка** — плитки по всем разделам: атаки за 24 ч и динамика, трафик (RPS/p95/5xx),
  зал ожидания, минимальный срок TLS, статус защиты (гео/skip), последний тест ёмкости.
  Клик по плитке открывает соответствующий раздел; кнопка «Обновить сводку» перечитывает данные.
- **Анализ атак** — реальные детекты SafeLine за период (1 ч / 6 ч / 24 ч / 7 д / 30 д):
  всего атак, заблокировано, уникальные IP, типы атак, динамика к прошлому периоду,
  диаграмма по времени, топы (типы, страны, сайты, IP, URL, действия). Служебные записи
  (Deny/Allow/Non-Attack) не учитываются. Экспорт CSV/JSON.

## CrowdSec (раздел «Безопасность»)

- **Баны** — активные (IP, страна, AS, сценарий, срок), бан вручную на 1 ч–7 д,
  снятие бана. Наведите на плитки метрик — у каждой есть пояснение.

## Проксирование

Аналитика из собственного `access_log` WAF-прокси (файл `slext_traffic.log`), без внешних систем:

- **KPI:** запросы, уникальные IP, средний RPS, Apdex (T=250 мс), p50, p95, 5xx %, средние
  накладные WAF. Дополнительная строка: p99, 4xx, доля ботов, p95 ошибок, трафик in/out.
- **Динамика** — один график с переключателем метрик: запросы / трафик / задержки / ошибки.
- **Распределение задержек** — гистограмма (0–10 … >3200 мс).
- **Статусы и методы** — разбивка по HTTP-кодам и методам.
- **Топ путей** — запросы, среднее время, p95, доля ошибок.
- **Источники (referer)** — откуда приходят посетители.
- **Апстрим и накладные WAF** — время бэкенда против полного времени ответа.
- **Самые медленные запросы** — топ-12 с деталями.

Тестовый трафик SLExt из статистики исключается. Ротация лога — при >100 МБ.

## DNS и TLS

- **KPI:** домены сайта, доступность DNS за 24 ч, среднее время ответа, минимальный срок TLS.
- **График задержки DNS** по доменам (история 2 суток, проверка каждые 5 минут).
- **Таблица:** A-записи с TTL, AAAA, время DNS, SPF/DMARC (есть/нет), TLS (издатель, дней
  до истечения с подсветкой <14 дней), время последней проверки.
- Кнопка **«Проверить сейчас»** — внеочередная полная проверка (в т.ч. NS/MX/TXT).

## Зал ожидания (SLExt)

Собственный зал очереди: cookie-гейт в nginx + наш API. Считает **посетителей** (по cookie),
а не запросы, поэтому обычная загрузка страниц никогда не «упирается» в очередь.

- **Вкл/выкл** очереди по каждому сайту (кнопка «Включить/Выключить»), источник изменения
  (вручную / расписание / авто) виден в блоке.
- **Настройки:** порог одновременных посетителей, удержание слота (сек), максимальная очередь —
  применяются мгновенно, для каждого сайта свои. «Сбросить очередь» очищает состояние и счётчики.
- **Статистика:** активны сейчас, в очереди, обслужено за активацию, пик очереди.
- **Расписание** — дни недели и интервал времени.
- **Авто-режим по нагрузке (детерминированный):** считается реальный трафик (HTML-запросы
  живых посетителей, боты и служебные пути исключены) в запросах/мин. Включение — при
  превышении порога N проверок подряд (каждые 20 с) и не раньше «запрета» после ручного
  выключения; выключение — при трафике ниже порога M проверок подряд после «паузы».
  Ручное переключение всегда приоритетнее. Политика покрыта юнит-тестами; решения — в журнале.
- **Страница очереди** — наша: свои тексты, бренд; живая позиция, автоперезагрузка при
  допуске; при «очередь переполнена» — повтор автоматически.
- **Тестовый контур:** сервис `slext-teststub` + сайт `test.slext.local` — все сценарии зала
  проверяются без риска для боевого сайта.

## Тест ёмкости

- **Режимы:** «напрямую в бэкенд» (по умолчанию — защита не затрагивается) и «через WAF»
  (боевой путь; защита приостанавливается автоматически на время теста и возвращается после).
- **Параметры:** макс. параллельных, длительность стадии, стоп-порог p95, стоп-порог ошибок,
  лимит времени.
- **Алгоритм:** ступени 1 → 2 → 4 → …, на каждой RPS, p50/p95/p99, ошибки, блокировки.
  Остановка при деградации, блокировке защитой, плато RPS, максимуме или лимите времени.
- **Отчёт:** итог, анализ (устойчивая пропускная способность, первая деградация, причины
  остановки), стадии с числом запросов и длительностью, статус защиты, рекомендации для
  зала ожидания (лимит одновременных, пороги включения/выключения) и кнопка «Подставить
  в зал ожидания».
- **Архив** — последние 10 отчётов: открыть в панели, скачать HTML, удалить.

## Страницы

- Редактор страниц ошибок **403 / 404 / 429 / 465 / 466 / 502 / 504**: включение, бренд,
  заголовок и текст каждой страницы, превью. Оформление — в стиле NRG / INDEX, палитра
  фиксирована.
- Работает вместо Pro-раздела «Blocking Pages → Custom HTML» и применяется ко всем сайтам.

## Безопасность

- **Skip decryption page** — аналог Pro-функции: первый заход проходит наш гейт (без
  страницы расшифровки), повторные — напрямую в бэкенд. Защита при этом сохраняется.
- **Гео-блокировка** — блокировка или белый список по странам (данные ipdeny), применяется
  ко всем сайтам SafeLine; кнопка «Синхронизировать списки» скачивает и применяет CIDR.
- **API-маршруты (whitelist и rate-limit)** — по выбранному сайту: запросы по указанным
  путям (по умолчанию `/api/v1/`) идут в обход JS-челленджа SafeLine — страницы `/` и
  `/login` остаются под проверкой; на эти же пути включается лимит запросов с одного IP
  (по умолчанию 120/мин, настраивается, с `burst`) — предохранитель поверх лимитов
  приложения. Фильтрация WAF на пути сохраняется, конфиги идемпотентны.

## Уведомления

Telegram (токен бота, chat id, минимальный риск, тест), Discord (webhook, тест),
правила алертов по метрикам (атаки / блокировки / высокий риск) с порогами, окнами и
кулдаунами, syslog (UDP/TCP, тест), автобэкапы конфигурации (час, срок хранения, ручной запуск).

## Доступ (в оригинальном интерфейсе)

Матрица прав живёт **не в SLExt, а в нативном разделе панели**: SafeLine → **Settings** →
блок **«SLExt: Доступ»** (виден только администраторам, право `access.manage`). Там
настраиваются роли (Администратор / Оператор / Наблюдатель / Настраиваемый), 26 прав по
разделам и ограничение по доменам. Подробно — [access.md](access.md).
